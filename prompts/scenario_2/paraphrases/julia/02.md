Estimate the time-varying effective reproduction number (Rt), defined as the mean number of secondary infections generated by someone infected at time t, using daily case data from an infectious disease outbreak.

Scope and data sources
- Analysis window: 150 consecutive days, spanning 2023-01-01 through 2023-05-30.
- Input file: data/cases.csv
  - Columns:
    - date: in YYYY-MM-DD format
    - cases: integer counts

Fixed epidemiological inputs (no uncertainty propagation; taken as known from external studies)
- Generation interval: Gamma distribution with mean 5.5 days and standard deviation 2 days.
- Reporting delay (infection to observed case): Log-normal distribution with mean 5 days and standard deviation 2 days.

Observed-data structure to incorporate
- A nonzero reporting delay links infections to reported cases, distributed as specified above.
- Weekly periodicity in reporting due to weekend effects.
- The fraction of infections that are detected as cases changes over time; this ascertainment path is unknown and must be inferred.
- Observation noise exceeds Poisson variance (overdispersion).

Modelling requirements
- Base the model on the renewal equation.
- Explicitly link latent infections to observed cases through the reporting delay.
- Include:
  - a day-of-week reporting component,
  - time-varying ascertainment,
  - and overdispersed observation noise (e.g., negative binomial).

Implementation constraints
- Use Julia. Standard Julia packages are available.
- Employ Turing.jl for any probabilistic/Bayesian components. A Turing.jl API reference is available in turing_api_docs.md.

Deliverables
- Provide daily point estimates of Rt for the entire 150-day period.
- Write the final estimates to outputs/rt_estimates.csv with columns:
  - date (YYYY-MM-DD)
  - Rt_median (point estimate)
  - Rt_lower (5th-percentile credible/confidence bound; optional but encouraged)
  - Rt_upper (95th-percentile credible/confidence bound; optional but encouraged)

Quality and robustness
- If your code encounters errors, identify the cause and correct them.
- If the inferred Rt trajectory appears implausible, revise the model accordingly and re-run.
