# Dynamic Reproduction Number Estimation from Outbreak Data

For an ongoing infectious disease outbreak, your objective is to derive daily point estimates of the time-varying effective reproduction number, $R_t$. This metric represents the average number of secondary infections generated by an individual infected at time $t$, and it must be computed from the provided observational data.

## Input Data

The observational dataset spans a period of 150 days, commencing on 2023-01-01 and concluding on 2023-05-30. This information is located in the file `data/cases.csv`, which contains two columns: `date` (formatted as YYYY-MM-DD) and `cases` (representing integer counts).

## Fixed Epidemiological Characteristics

Parameters describing the pathogen's epidemiology are provided as constants, derived from prior research. Uncertainty propagation for these values is not required; they should be treated as deterministic inputs.

*   **Generation Interval:** Characterized by a Gamma distribution, with a mean of 5.5 days and a standard deviation of 2 days.
*   **Reporting Delay:** The time from infection to case observation follows a log-normal distribution, having a mean of 5 days and a standard deviation of 2 days.

## Inherent Data Properties

The observed data exhibits several key structural attributes that must be addressed:

*   A delay exists between the actual infection event and its observation as a reported case; this delay's distribution is specified in the "Fixed Epidemiological Characteristics" section.
*   Case counts demonstrate a cyclical pattern over a seven-day period, attributed to diminished reporting activities on weekends.
*   The ascertainment rate, defined as the proportion of total infections recorded as cases, is not constant over time. Its temporal evolution is unprovided and must be inferred directly from the dataset.
*   The noise associated with observations is not consistent with a simple Poisson process; it displays overdispersion.

## Implementation Requirements

Your primary deliverable is a set of daily point estimates for $R_t$, covering the entire 150-day observation window.

### Model Specification

The underlying epidemiological model must be founded upon the renewal equation. It is essential to establish a link between the unobserved infection process and the reported case data, incorporating the defined reporting delay. Your model must explicitly integrate the following phenomena:

*   The observed day-of-week periodicity in reporting.
*   Fluctuations in the ascertainment rate over time.
*   The overdispersed nature of observational noise (e.g., employing a negative binomial distribution).

### Development Environment

All code must be written in Julia. Access to standard Julia packages is permitted. For any probabilistic or Bayesian modeling components, you are required to utilize Turing.jl, referring to the provided API documentation in `turing_api_docs.md`.

### Output Format

The computed $R_t$ estimates should be stored in `outputs/rt_estimates.csv`. This file must contain the following columns:

*   `date` (in YYYY-MM-DD format)
*   `Rt_median` (the central point estimate)
*   `Rt_lower` (representing the 5th-percentile credible or confidence bound; inclusion is optional but recommended)
*   `Rt_upper` (representing the 95th-percentile credible or confidence bound; inclusion is optional but recommended)

### Robustness and Validation

Should your implementation encounter runtime errors, you are expected to debug and resolve them. Furthermore, if the generated results appear inconsistent with expectations, refine your model as necessary and repeat the estimation process.
