# Time-varying reproduction number estimation with structured observation model

You will analyze daily infectious disease outbreak counts to estimate the time-varying effective reproduction number $R_t$, which represents the mean number of secondary infections generated by an individual infected at time $t$.

## Input data

Daily observations span 150 days from 2023-01-01 through 2023-05-30. Data location:

- `data/cases.csv` containing columns `date` (YYYY-MM-DD format) and `cases` (integer).

## Fixed epidemiological parameters

The following distributions are derived from external pathogen studies and should be treated as known constants without uncertainty propagation:

- Generation interval: Gamma distribution with mean 5.5 days and standard deviation 2 days.
- Reporting delay (time from infection to case observation): log-normal distribution with mean 5 days and standard deviation 2 days.

## Data structure characteristics

- Case observation lags behind infection according to the reporting delay distribution specified above.
- Weekly periodicity in counts occurs due to weekend underreporting.
- Time-varying ascertainment (the fraction of infections recorded as cases) has an unknown trajectory requiring estimation.
- Observation noise exhibits overdispersion compared to a homogeneous Poisson process.

## Requirements

Generate daily $R_t$ point estimates covering the entire observation period.

**Base your model on the renewal equation.** Link the latent infection process to observed cases through the reporting delay. Explicitly model:

- day-of-week reporting periodicity,
- time-varying ascertainment, and
- overdispersed observation noise (e.g., negative binomial distribution).

**Implement using the EpiAware.jl Julia package.** Build the model using EpiAware primitives. Refer to `epiaware_docs.md` for the EpiAware API reference containing available types and functions.

Write final $R_t$ estimates to `outputs/rt_estimates.csv` with these columns:

- `date` (YYYY-MM-DD format)
- `Rt_median` (point estimate)
- `Rt_lower` (5th-percentile credible/confidence bound, optional but encouraged)
- `Rt_upper` (95th-percentile credible/confidence bound, optional but encouraged)

Diagnose and resolve any errors in your code. If results appear implausible, modify the model and rerun.
