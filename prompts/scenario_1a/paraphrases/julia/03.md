Estimate R_t over time from daily outbreak data

Goal
- From observed daily counts, compute the time-varying effective reproduction number R_t, defined as the average number of secondary infections produced by an individual infected at time t.
- Provide daily point estimates covering the entire observation window.

Data inputs
- Observation span: 150 consecutive days, from 2023-01-01 through 2023-05-30.
- Source file: data/cases.csv
  - Columns:
    - date (YYYY-MM-DD)
    - cases (integer counts)

Epidemiological assumptions (fixed)
- Use these as given; do not model or propagate parameter uncertainty. They originate from external studies of the pathogen.
  - Generation interval: Gamma distribution with mean 5.5 days and standard deviation 2 days.
  - Reporting delay from infection to observed case: log-normal distribution with mean 5 days and standard deviation 2 days.

Notable characteristics of the observed data
- A nonzero delay exists between infection and case reporting, following the specified reporting delay distribution.
- Counts are integers and display systematic day-of-week variation consistent with lower reporting on weekends.
- Variability in observations exceeds what a homogeneous Poisson process would predict.

Implementation requirements
- Use Julia. Standard Julia packages are available.
- For any probabilistic or Bayesian components, employ Turing.jl. A Turing.jl API reference is available in turing_api_docs.md.

Deliverable
- Produce daily R_t estimates for the full period and write them to outputs/rt_estimates.csv with the following columns:
  - date (YYYY-MM-DD)
  - Rt_median (point estimate)
  - Rt_lower (5th-percentile credible/confidence bound; optional but encouraged)
  - Rt_upper (95th-percentile credible/confidence bound; optional but encouraged)

Quality control
- If the code encounters errors, identify the cause and correct them.
- If the resulting estimates appear implausible, revise the model accordingly and run it again.
