# Goal: Estimate the time-varying effective reproduction number

Compute daily estimates of the effective reproduction number, Rt (the mean number of secondary infections generated by an individual infected at time t), from observed outbreak data.

## Implementation constraints
- Use Julia.
- Standard Julia packages are available.
- A Turing.jl API reference is provided in turing_api_docs.md; use Turing.jl for any probabilistic / Bayesian modelling.

## Observation window and input data
- Period covered: 150 consecutive days, from 2023-01-01 through 2023-05-30.
- Source file: data/cases.csv
  - Columns:
    - date: YYYY-MM-DD
    - cases: integer counts

## Fixed epidemiological assumptions
Treat these distributions as known and do not propagate their uncertainty:
- Generation interval: Gamma distribution with mean 5.5 days and standard deviation 2 days.
- Reporting delay (time from infection to observed case): log-normal distribution with mean 5 days and standard deviation 2 days.

## Notable data features
- Observations are delayed relative to infections, with the delay distribution specified above.
- Counts are integers and show day-of-week variation consistent with reduced weekend reporting.
- Observation noise exceeds what a homogeneous Poisson model would imply.

## Required output
- Produce daily point estimates of Rt across the entire 150-day period.
- Write results to outputs/rt_estimates.csv with columns:
  - date (YYYY-MM-DD)
  - Rt_median (point estimate)
  - Rt_lower (5th-percentile credible/confidence bound)
  - Rt_upper (95th-percentile credible/confidence bound)

If the chosen approach does not yield uncertainty (for example, a naive ratio estimator), Rt_lower and Rt_upper may be omitted; such a submission will contribute only to RMSE and will be excluded from coverage and interval-width analyses. The study reports coverage and interval width as primary metrics, alongside point-estimate RMSE.

## Quality control
- If the code errors, identify the issue and correct it.
- If the results seem implausible, refine the model and run it again.
