# Time-Varying Reproduction Number Estimation

The primary objective is to derive daily estimates of the time-varying effective reproduction number, $R_t$. This metric, defined as the average number of secondary infections initiated by an individual infected at time $t$, is to be calculated from observed daily outbreak data.

## Input Data Description

The observational dataset covers a period of 150 days, commencing on 2023-01-01 and concluding on 2023-05-30. This information is stored in the file `data/cases.csv`. Within this file, you will find two columns: `date`, formatted as YYYY-MM-DD, and `cases`, which contains integer counts.

## Fixed Epidemiological Parameters

Certain epidemiological distributions, sourced from external pathogen research, are provided and must be considered as fixed, known values. Uncertainty propagation for these parameters is not required.

- The generation interval is specified as a Gamma distribution with a mean of 5.5 days and a standard deviation of 2 days.
- The reporting delay, which describes the duration from infection to the observation of a case, follows a log-normal distribution with a mean of 5 days and a standard deviation of 2 days.

## Inherent Data Characteristics

The input data exhibits specific structural attributes:

- A reporting delay exists between the moment of infection and the observation of a case, whose distribution is detailed in the parameters section.
- Case counts are recorded as integer values.
- The data displays fluctuations by day of the week, indicative of diminished reporting activity during weekends.
- The level of observation noise present in the data surpasses what a homogeneous Poisson model would predict.

## Implementation and Output Requirements

The task necessitates generating daily point estimates for $R_t$ across the entirety of the observation period.

### Technical Environment

- All development must be conducted in Julia.
- Standard Julia packages are accessible for use.
- Any probabilistic or Bayesian modeling components are to be implemented using Turing.jl, with an API reference available in `turing_api_docs.md`.

### Output Specification

- The computed $R_t$ estimates must be stored in `outputs/rt_estimates.csv`.
- This output file must contain the following columns:
    - `date` (formatted as YYYY-MM-DD)
    - `Rt_median` (serving as the primary point estimate)
- Inclusion of credible or confidence bounds is optional, but recommended:
    - `Rt_lower` (representing the 5th-percentile bound)
    - `Rt_upper` (representing the 95th-percentile bound)

### Error Handling and Model Iteration

- Should the code produce errors, it is essential to diagnose and resolve them.
- If the derived results appear to lack plausibility, the model should be refined and the estimation process repeated.
