# Time-varying reproduction number estimation

Your assignment is to estimate the effective reproduction number $R_t$ over time (defined as the mean count of secondary infections generated by a person infected at time $t$) using observed daily case counts from an infectious disease outbreak.

## Input data

Daily case counts span 150 days from 2023-01-01 through 2023-05-30. The input file is:

- `data/cases.csv` containing columns `date` (formatted YYYY-MM-DD) and `cases` (integer values).

## Fixed epidemiological parameters

The following distributional parameters are derived from external pathogen studies. Use them as fixed constants without propagating uncertainty.

- Generation interval: Gamma distribution with mean 5.5 days and standard deviation 2 days.
- Reporting delay (time from infection to case observation): log-normal distribution with mean 5 days and standard deviation 2 days.

## Data characteristics

- Case observations are delayed relative to infection events according to the reporting delay distribution specified above.
- Case counts are integers and display day-of-week patterns reflecting lower weekend reporting.
- Observation noise exceeds what a homogeneous Poisson model would predict.

## Requirements

Generate daily $R_t$ point estimates covering the entire observation period.

**Language requirement: Julia.** You may use standard Julia packages. For probabilistic or Bayesian modelling, use Turing.jl; consult the API reference provided in `turing_api_docs.md`.

Write your final $R_t$ estimates to `outputs/rt_estimates.csv` with these columns:

- `date` (formatted YYYY-MM-DD)
- `Rt_median` (point estimate)
- `Rt_lower` (5th-percentile credible/confidence bound)
- `Rt_upper` (95th-percentile credible/confidence bound)

Primary evaluation metrics include coverage, interval width, and point-estimate RMSE. Methods that do not generate uncertainty quantification (such as naive ratio estimators) may exclude `Rt_lower` and `Rt_upper`; such submissions are evaluated only on RMSE and excluded from coverage and width evaluation.

Diagnose and resolve any errors your code produces. If results appear implausible, modify the model and execute again.
