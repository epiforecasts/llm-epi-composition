# Computation of the Time-Varying Effective Reproduction Number

This task involves calculating the time-varying effective reproduction number, $R_t$, which represents the average number of secondary infections generated by an individual infected at time $t$. This estimation will be performed using daily infection counts from a disease outbreak.

## Input Data Details

Observations span 150 days, from January 1, 2023, to May 30, 2023. These daily counts are provided in the file `data/cases.csv`, which contains two columns:
- `date` (formatted as YYYY-MM-DD)
- `cases` (representing integer counts)

## Fixed Epidemiological Parameters

The following parameters, derived from external pathogen studies, should be considered as fixed and known, with no requirement to account for their inherent uncertainty:
- **Generation Interval**: Modeled as a Gamma distribution with a mean of 5.5 days and a standard deviation of 2 days.
- **Reporting Delay** (time from infection to case observation): Characterized by a log-normal distribution, having a mean of 5 days and a standard deviation of 2 days.

## Characteristics of the Input Data

- A reporting delay exists between the actual infection event and its observation as a reported case; its distribution is specified previously.
- Case counts are integers and display weekly periodicity, indicative of decreased reporting activity during weekends.
- The level of observation noise surpasses what a simple homogeneous Poisson model would predict.

## Output Requirements and Constraints

The primary objective is to generate daily point estimates for $R_t$ covering the entire 150-day observation window.

Any programming language, computational framework, or estimation methodology is permissible.

The final $R_t$ estimates must be stored in the file `outputs/rt_estimates.csv`. This file should include the following columns:
- `date` (in YYYY-MM-DD format)
- `Rt_median` (representing the point estimate)
- `Rt_lower` (the 5th-percentile credible or confidence bound)
- `Rt_upper` (the 95th-percentile credible or confidence bound)

Note that the evaluation framework prioritizes coverage and interval width, in addition to Root Mean Square Error (RMSE) for point estimates. Submissions lacking uncertainty quantification (i.e., omitting `Rt_lower` and `Rt_upper`, as might occur with a basic ratio estimator) will contribute solely to RMSE assessments and will not be considered for coverage or interval width analyses.

Should your implementation produce errors, they must be diagnosed and resolved. Similarly, if the derived results appear to be implausible, the underlying model should be adjusted and the estimation process repeated.
