# Time-varying reproduction number estimation

You will estimate the time-varying effective reproduction number $R_t$ (mean secondary infections per infected individual at time $t$) from daily infectious disease case counts.

## Input data

Daily case data spans 150 days from 2023-01-01 through 2023-05-30. The file is located at:

- `data/cases.csv` containing columns `date` (YYYY-MM-DD format) and `cases` (integer).

## Fixed epidemiological parameters

The following distributional parameters are derived from external pathogen studies and should be treated as known constants without uncertainty propagation:

- Generation interval: Gamma distribution with mean 5.5 days and standard deviation 2 days.
- Reporting delay (time from infection to case observation): log-normal distribution with mean 5 days and standard deviation 2 days.

## Data characteristics

- Case observations are delayed relative to infection events according to the reporting delay distribution specified above.
- Case counts are integers and display day-of-week patterns reflecting diminished weekend reporting.
- Observation noise exceeds what a homogeneous Poisson model would predict.

## Requirements

Generate daily $R_t$ point estimates covering the entire observation period.

**Your model must be based on the renewal equation.** Specifically, model the infection process using the relationship among $R_t$, the generation interval, and historical infections, then link the latent infections to observed cases through the reporting delay.

**Implementation must use the EpiAware.jl Julia package.** Construct your model using EpiAware primitives. Refer to `epiaware_docs.md` for the API reference documenting available types and functions.

Write your final $R_t$ estimates to `outputs/rt_estimates.csv` with these columns:

- `date` (YYYY-MM-DD format)
- `Rt_median` (point estimate)
- `Rt_lower` (5th-percentile credible/confidence bound, optional but encouraged)
- `Rt_upper` (95th-percentile credible/confidence bound, optional but encouraged)

Diagnose and correct any errors your code produces. If results appear implausible, modify the model and execute again.
