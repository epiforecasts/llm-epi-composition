# Determination of the Time-Varying Effective Reproduction Number

From a dataset of daily infectious disease counts, the objective is to calculate the time-varying effective reproduction number, denoted as $R_t$. This metric represents the average quantity of secondary infections generated by an individual who became infected at time $t$.

## Input Data

The data for this analysis spans a 150-day observation window, commencing on 2023-01-01 and concluding on 2023-05-30. Case observations are provided in the file `data/cases.csv`. This file contains two columns: `date`, formatted as YYYY-MM-DD, and `cases`, which are recorded as integer counts.

## Fixed Epidemiological Parameters

Parameters related to the pathogen's epidemiology, derived from external research, should be treated as constants without requiring uncertainty propagation.

-   **Generation Interval:** Follows a Gamma distribution with a mean of 5.5 days and a standard deviation of 2 days.
-   **Reporting Delay:** The time from infection to case observation is modeled by a log-normal distribution, characterized by a mean of 5 days and a standard deviation of 2 days.

## Data Characteristics

Several inherent characteristics are present in the provided dataset:

-   A delay exists between the actual infection event and its observation as a reported case, consistent with the specified reporting delay distribution.
-   The recorded case counts are exclusively integers.
-   The data display weekly periodicity, specifically day-of-week variations indicative of decreased reporting activity during weekends.
-   The level of observation noise exceeds what would typically be anticipated from a homogeneous Poisson process.

## Implementation Requirements

The deliverable is a set of daily point estimates for $R_t$, covering the entirety of the observation period.

The modeling approach must be founded upon the renewal equation. This involves utilizing the interplay between $R_t$, the generation interval, and historical infection events to construct the infection process model, subsequently linking this latent infection process to the observed case data through the reporting delay.

The implementation must be in Julia. Standard Julia packages are accessible. For any probabilistic or Bayesian modeling components, Turing.jl must be employed; a relevant API reference can be found in `turing_api_docs.md`.

The computed $R_t$ estimates are to be stored in `outputs/rt_estimates.csv`. This output file should include the following columns:

-   `date`: Formatted as YYYY-MM-DD.
-   `Rt_median`: The primary point estimate.
-   `Rt_lower`: An optional, but recommended, 5th-percentile credible or confidence bound.
-   `Rt_upper`: An optional, but recommended, 95th-percentile credible or confidence bound.

Should the code encounter errors, these must be diagnosed and resolved. In instances where the generated results appear inconsistent with expectations, model adjustments and subsequent re-execution are required.
