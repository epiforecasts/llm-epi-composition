# Multi-stream estimation of a common time-varying effective reproduction number

Your objective is to infer a unified time-varying effective reproduction number $R_t$ from three distinct observation types recorded during an infectious disease outbreak: cases, hospitalisations, and deaths. These three data streams represent independent observations of a single underlying epidemic process.

## Input data files

Daily counts span 150 days from 2023-01-01 through 2023-05-30. The files are:

- `data/cases.csv` — contains columns `date`, `cases`.
- `data/hospitalisations.csv` — contains columns `date`, `hospitalisations`.
- `data/deaths.csv` — contains columns `date`, `deaths`.

## Fixed epidemiological parameters

The following parameter values are derived from external pathogen studies and should be treated as known constants without uncertainty propagation:

- Generation interval: Gamma distribution with mean 5.5 days and standard deviation 2 days.
- Reporting delay (infection to observation), log-normal distribution:
  - Cases: mean 5 days, standard deviation 2 days.
  - Hospitalisations: mean 10 days, standard deviation 3 days.
  - Deaths: mean 20 days, standard deviation 5 days.

## Data characteristics

- The three observation streams are independent measurements of the same epidemic and are driven by a single shared $R_t$ time series.
- Each stream has a distinct reporting delay (specified above) and a distinct time-varying ascertainment rate (the fraction of infections ultimately captured in that stream). Ascertainment rates vary over time, differ between streams, and are not known.
- Weekly reporting patterns are present in the count data.
- Observation noise exhibits overdispersion compared to a homogeneous Poisson process.

## Requirements

Generate daily point estimates for a unified $R_t$ trajectory that reconciles all three observation streams. Apply the renewal equation to model the infection process. Explicitly incorporate stream-specific reporting delays, stream-specific time-varying ascertainment rates, day-of-week effects, and overdispersed observation noise.

**Implementation must use the EpiAware.jl Julia package.** Build the model using EpiAware's primitive components. Refer to `epiaware_docs.md` for the API reference detailing available types and functions.

Write the final $R_t$ estimates to `outputs/rt_estimates.csv` with the following columns:

- `date` (format YYYY-MM-DD)
- `Rt_median` (point estimate)
- `Rt_lower` (5th-percentile credible/confidence bound, optional but encouraged)
- `Rt_upper` (95th-percentile credible/confidence bound, optional but encouraged)

Diagnose and resolve any errors that arise during execution. If outputs appear implausible, modify the model and re-execute.
