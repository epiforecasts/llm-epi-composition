# Infer a common time-varying reproduction number from multiple surveillance series

You are working with daily counts from an outbreak recorded through three surveillance channels: cases, hospitalisations, and deaths. Each channel provides an independent view of the same epidemic. The goal is to recover one shared effective reproduction number Rt that aligns with all three series over time.

## Inputs

Observation window: 150 days spanning 2023-01-01 to 2023-05-30.

Data files and schema:
- data/cases.csv with columns: date, cases
- data/hospitalisations.csv with columns: date, hospitalisations
- data/deaths.csv with columns: date, deaths

## Fixed epidemiological quantities

Treat the following as known without uncertainty (no uncertainty propagation required):
- Generation interval: Gamma, mean 5.5 days, standard deviation 2 days.
- Infection-to-observation reporting delays (log-normal) by stream:
  - Cases: mean 5 days, standard deviation 2 days
  - Hospitalisations: mean 10 days, standard deviation 3 days
  - Deaths: mean 20 days, standard deviation 5 days

## Data structure and assumptions

- The three series are independent measurements of the same outbreak and must share a single Rt path.
- Each stream has its own reporting delay as above.
- Each stream has its own time-varying ascertainment (the fraction of infections that ultimately appear in that stream); these trajectories are different across streams and are unknown.
- There is a weekly (day-of-week) reporting pattern.
- Measurement noise is overdispersed compared to a homogeneous Poisson process.

## What to produce

Generate daily point estimates of one Rt trajectory that is consistent with all three data streams. Base the infection dynamics on the renewal equation. Explicitly model:
- Stream-specific delays
- Stream-specific, time-varying ascertainment
- Day-of-week reporting effects
- Overdispersed observation noise

## Implementation constraints

- Use Julia.
- Standard Julia packages are available.
- A Turing.jl API reference is provided in turing_api_docs.md; use Turing.jl for any probabilistic / Bayesian modelling.

## Output file

Write results to outputs/rt_estimates.csv with columns:
- date (YYYY-MM-DD)
- Rt_median (point estimate)
- Rt_lower (5th-percentile bound; optional but encouraged)
- Rt_upper (95th-percentile bound; optional but encouraged)

## Robustness

If the code throws errors, investigate and resolve them. If the resulting estimates appear implausible, revise the model and run it again.
