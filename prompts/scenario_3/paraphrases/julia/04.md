# Determine a Unified Time-Varying Reproduction Number from Diverse Data Sources

The objective is to derive a singular, time-dependent effective reproduction number ($R_t$) for an infectious disease outbreak. This $R_t$ must reflect daily count data collected from three distinct, yet independent, observation channels: cases, hospitalisations, and deaths. These streams each provide an independent view of the identical underlying epidemic.

## Input Data

Data encompasses a 150-day observation window, spanning from 2023-01-01 through 2023-05-30. The required input files are:

*   `data/cases.csv`: Contains `date` and `cases` columns.
*   `data/hospitalisations.csv`: Contains `date` and `hospitalisations` columns.
*   `data/deaths.csv`: Contains `date` and `deaths` columns.

## Epidemiological Parameters

The following epidemiological parameters are provided as fixed values, derived from external pathogen studies; their uncertainty should not be propagated.

*   The generation interval follows a Gamma distribution with a mean of 5.5 days and a standard deviation of 2 days.
*   Reporting delays, representing the time from infection to observation, are modelled as log-normal distributions:
    *   For cases: mean of 5 days, standard deviation of 2 days.
    *   For hospitalisations: mean of 10 days, standard deviation of 3 days.
    *   For deaths: mean of 20 days, standard deviation of 5 days.

## Data Characteristics

Key characteristics of the data streams include:

*   A shared $R_t$ trajectory underpins all three series, which are considered independent observations of the same epidemic.
*   Each stream possesses a unique reporting delay (as detailed previously) and its own time-varying ascertainment rate, defined as the proportion of infections ultimately recorded within that stream. These ascertainment trajectories are distinct for each stream and are not provided.
*   A weekly reporting pattern is evident in the daily counts.
*   The observation noise exhibits overdispersion when compared to a homogeneous Poisson process.

## Requirements

Your task is to generate daily point estimates for a single $R_t$ trajectory that harmonises with all three data streams. The infection process should be modelled using the renewal equation. It is imperative to explicitly incorporate stream-specific delays, time-varying ascertainment unique to each stream, the observed day-of-week cycle, and the overdispersed nature of the observation noise.

The implementation must be in **Julia**, utilising standard Julia packages. For any probabilistic or Bayesian modelling components, Turing.jl is to be employed; an API reference is accessible via `turing_api_docs.md`.

The final $R_t$ estimates must be stored in `outputs/rt_estimates.csv`, structured with the following columns:

*   `date`: Formatted as YYYY-MM-DD.
*   `Rt_median`: Represents the point estimate.
*   `Rt_lower`: An optional, but recommended, 5th-percentile credible or confidence bound.
*   `Rt_upper`: An optional, but recommended, 95th-percentile credible or confidence bound.

Should the code encounter errors, diagnosis and resolution are required. In cases where results appear implausible, the model must be adjusted and the execution re-initiated.
