# Joint estimation of a time-varying effective reproduction number from three surveillance data sources

You will work with daily surveillance data from an infectious disease epidemic. The dataset comprises three observation types: cases, hospitalisations, and deaths. These three streams independently observe the same underlying transmission process. You must infer a unified time-varying effective reproduction number $R_t$ that reconciles all three data sources.

## Input data

Daily observations span 150 days from 2023-01-01 through 2023-05-30. Data files are located at:

- `data/cases.csv` — containing columns `date`, `cases`.
- `data/hospitalisations.csv` — containing columns `date`, `hospitalisations`.
- `data/deaths.csv` — containing columns `date`, `deaths`.

## Fixed epidemiological parameters

The following parameters derive from external pathogen studies. Treat these as known constants without uncertainty propagation.

- Generation interval: Gamma distribution with mean 5.5 days and standard deviation 2 days.
- Reporting delay (infection to observation), log-normal distribution:
  - Cases: mean 5 days, standard deviation 2 days.
  - Hospitalisations: mean 10 days, standard deviation 3 days.
  - Deaths: mean 20 days, standard deviation 5 days.

## Data structure

- The three observation streams independently measure the same epidemic and are governed by a single shared $R_t$ time series.
- Each stream possesses its own reporting delay (specified above) and its own time-varying ascertainment rate (the fraction of infections ultimately captured by that stream). Ascertainment varies over time, differs among streams, and is not directly observed.
- A weekly reporting pattern is present in the count data.
- Observation noise exhibits overdispersion compared to a homogeneous Poisson process.

## Requirements

Generate daily point estimates for a unified $R_t$ time series that is coherent across all three observation streams. Model the infection dynamics using the renewal equation. Explicitly incorporate stream-specific reporting delays, stream-specific time-varying ascertainment, day-of-week effects, and overdispersed observation noise.

**The implementation must be in Julia.** You may use standard Julia packages. Consult `turing_api_docs.md` for Turing.jl API documentation; employ Turing.jl for probabilistic or Bayesian inference.

Write the final $R_t$ estimates to `outputs/rt_estimates.csv` with the following columns:

- `date` (format YYYY-MM-DD)
- `Rt_median` (point estimate)
- `Rt_lower` (5th-percentile credible/confidence bound, optional but encouraged)
- `Rt_upper` (95th-percentile credible/confidence bound, optional but encouraged)

Should your code encounter errors, identify and resolve them. If outputs appear implausible, modify the model and execute again.
